## 2. データ構造（追加分）

`state.version` を **3** に上げる。v2の保存データは `normalize` が欠損を補って読める（変換は初期値の補完のみ）。localStorage キーは `storeSim:v2` のまま（キーを変えると自動保存が消えるため）。

```js
mgmt: {
  // 売上の全体像（円・人）
  revenue: null,          // 総売上（年）
  buyers: null,           // 購入客数（延べ）
  newBuyers: null,        // うち新規客数
  newRevenue: null,       // 新規客売上
  itemsPerBuyer: null,    // 買上点数（任意）
  // 顧客の構成
  activeCustomers: null,  // アクティブ顧客数（過去2年以内に購入）
  visits: { once: null, twice: null, threePlus: null }, // 来店回数別の客数
  dormant: null,          // 休眠客数（任意）
  // 商品・粗利（カテゴリ別。②の間口カテゴリ名を初期値に、自由に増減）
  products: [ { id, name, sales: null, grossMarginPct: null } ],
  inventory: null,        // 期末在庫金額（任意）
  // 費用の構造（年額）
  costs: { cogs: null, labor: null, rent: null, ads: null, other: null },
  // 集客効率（任意）
  funnel: { reservations: null, visits: null, deals: null },
  // 買替周期（任意・カテゴリ別）
  replacement: [ { id, name, cycleYears: null, pastBuyers: null } ], // pastBuyers＝直近サイクル年数ぶんの購入者数
  prev: null | { 同じ構造（prev を除く） }
},
plan: {
  ...既存,
  requiredProfit: null,     // 必要営業利益（円・年）
  existingGrowthPct: 0      // 既存客売上の見込み（現状比 %）
}
```

- 既存の `store.cogsRate` / `store.fixedCostMonthly` は残す。**経営数値が揃っていればそちらを優先**（§4-1）
- 既存の `channels` はデータ構造そのまま。画面上の置き場所を①「集客効率」ブロックへ移す

## 3. 計算（calc.js に `mgmt` 系を追加。純関数）

`Sim.calc.mgmt(state)` → 以下を返す。入力が欠けている項目は `null`（0で誤診断しない）。

| 出力 | 式 |
|---|---|
| existingRevenue | revenue − newRevenue |
| aov（客単価） | revenue ÷ buyers |
| newShare | newRevenue ÷ revenue |
| repeatRate | (twice + threePlus) ÷ (once + twice + threePlus) |
| visitFrequency | buyers ÷ activeCustomers |
| grossProfit / grossMarginPct | revenue − cogs ／ ÷ revenue |
| laborPct / rentPct / adsPct / otherPct | 各費用 ÷ revenue |
| fixedCosts | labor + rent + ads + other |
| operatingProfit / opMarginPct | grossProfit − fixedCosts ／ ÷ revenue |
| breakEven | fixedCosts ÷ grossMarginPct（grossMarginPct ≤ 0 は null） |
| safetyMargin | (revenue − breakEven) ÷ revenue |
| inventoryTurnMonths | inventory ÷ (cogs ÷ 12) |
| products[].share / contribution / contributionShare | sales ÷ Σsales ／ sales × gm% ／ ÷ Σcontribution |
| funnel.visitRate / dealRate | visits ÷ reservations ／ deals ÷ visits |
| replacement[].expectedBuyers | pastBuyers ÷ cycleYears（今後1年の買替見込み） |
| channels | 既存 `store().channels` と同じ（cpa・payback） |
| prev | 前期があれば同じ計算を前期に対して行い `prev` に格納 |

**間口分析との整合（`Sim.calc.consistency(state)`）**
- entryNewTotal ＝ Σ 間口カテゴリの新規獲得人数
- entryNewRevenue ＝ Σ 新規 ×（間口単価 ＋ 同日追加率×同日追加単価）（初回来店日の売上）
- newBuyersRatio ＝ entryNewTotal ÷ mgmt.newBuyers、newRevenueRatio ＝ entryNewRevenue ÷ mgmt.newRevenue
- どちらかが 0.8〜1.2 の外なら「ズレあり」（判定は analysis 側）

**経営版の効きどころ（`Sim.calc.mgmtLeverage(state)`）**：営業利益の増分を4本で比較
- 売上 +10%（仕入原価も同率で増える前提、固定費は不変）
- 粗利率 +1pt
- 人件費 −5%
- 広告費 −10%

**必要売上の逆算（`Sim.calc.requiredRevenue(state)`）**
- requiredRevenue ＝ (fixedCosts ＋ requiredProfit) ÷ grossMarginPct
- gap ＝ requiredRevenue − revenue
- existingForecast ＝ existingRevenue × (1 ＋ existingGrowthPct/100)
- newTarget ＝ requiredRevenue − existingForecast（＝間口で稼ぐべき1年の売上。負なら0）
- 「間口の目標売上（1年）に反映」で `plan.targetRevenue[0] = round(newTarget)` を書く

**原価率・固定費の優先（§4-1）**：`revenue>0 && cogs!=null` なら cogsRate ＝ cogs÷revenue×100、`fixedCosts` が揃えば fixedCostMonthly ＝ fixedCosts÷12 を**計算時に上書き**して使う（stateの手入力欄は書き換えない。画面に「経営数値から自動」と表示）。

## 4. ステップ① 経営数値（新規 `js/ui-mgmt.js`）

### 4-1. ブロック構成（各ブロックは折りたたみ可・任意項目は明記）
1. **売上の全体像**：総売上／購入客数／新規客数／新規客売上／買上点数（任意）。右側に自動値（既存客売上・客単価・新規売上比率）
2. **顧客の構成**：アクティブ顧客数／来店回数別客数（1回・2回・3回以上）／休眠客数（任意）。自動値（リピート率・年間来店頻度）
3. **商品・粗利**：カテゴリ別の売上と粗利率の表（行の追加・削除可。初回表示時に②の間口カテゴリ名を初期行として入れる「間口カテゴリ名を取り込む」ボタン）／期末在庫金額（任意）
4. **費用の構造**：仕入原価／人件費／家賃／広告宣伝費／その他経費。自動値（粗利率・各比率・営業利益・損益分岐点・安全余裕率）。原価率・固定費が経営数値から決まる旨の注記
5. **集客効率＋買替**：集客経路（②から移設・機能同一）／予約数→来店数→成約数（任意）／買替サイクル（カテゴリ名・サイクル年数・直近サイクル分の購入者数）
6. **前期の数字**（折りたたみ）：1〜5と同じ欄をもう1組（任意）
7. **貼り付け（2列形式）**：`項目名<TAB>値` の行を貼ると各欄に振り分け（§4-2）

### 4-2. 貼り付け（`Sim.paste.parseKeyValues(text)`）
- 1行＝「項目名 TAB（またはカンマ）値」。項目名は下記の日本語ラベルで判定（前後の空白・全角半角は吸収）。`¥` `,` `%` は除去
- 対応ラベル：総売上／購入客数／新規客数／新規客売上／買上点数／アクティブ顧客数／来店1回／来店2回／来店3回以上／休眠客数／期末在庫／仕入原価／人件費／家賃／広告宣伝費／その他経費／予約数／来店数／成約数
- 「前期 総売上」のように先頭に「前期」が付く行は prev へ
- 認識できない行は警告に列挙し取り込みは続行。プレビュー→「取り込む」の2段階（②と同じ作法）
- カテゴリ別の売上・粗利率と買替は表形式のため2列貼り付けの対象外（手入力）

### 4-3. 検証
- 金額・人数は0以上、粗利率は0〜100。範囲外は赤枠＋注記（v2と同じ仕組み）
- 整合の注記：newRevenue > revenue、newBuyers > buyers、来店回数別の合計 > activeCustomers のとき黄色の注記
- 未入力の自動値は「—」

## 5. ステップ③ 診断に「経営の健康度」を追加

間口診断（既存6ブロック）の**前**に置く。入力が無いブロックは「①経営数値を入れると表示されます」の1行だけ出す。

1. **収益構造**：売上→仕入原価→粗利→人件費→家賃→広告→その他→営業利益の**滝図**（インラインSVG）。横に損益分岐点売上・安全余裕率・営業利益率
2. **費用比率**：人件費率・家賃比率・広告費率・その他比率の横棒。前期があれば前期の棒を薄色で併記、目安値があれば線で表示
3. **顧客の構成**：新規／既存の売上比（100%積み上げ棒）、来店回数の分布（1回・2回・3回以上）、リピート率・年間来店頻度、休眠客数
4. **商品・粗利**：カテゴリ別に売上シェア・粗利率・粗利貢献シェアの表。「売上シェアより粗利貢献シェアが低い」カテゴリに印。在庫回転月数
5. **集客効率＋買替**：経路別CPA・粗利LTV÷CPA、予約→来店→成約の率、買替見込み客数と見込み売上（見込み客数×そのカテゴリの間口単価。間口に無ければ表示しない）
6. **整合チェック**：②の新規人数合計 vs ①の新規客数、②の初回来店売上 vs ①の新規客売上。比が0.8〜1.2の外なら「間口カテゴリの分け方か新規の数え方にズレがある可能性」と注記
7. **経営版の効きどころ**：4本の営業利益インパクトを横並び。最大のものを太字
8. **コメント**：既存の文体（「〜可能性があります」）で、粗利率・安全余裕率・リピート率・費用比率に触れる。物差しは前期＞目安値＞なし（なしのときは事実の記述のみ）

**目安値（任意入力）**に「粗利率／人件費率／家賃比率／広告費率／リピート率」を追加（§2の `benchmarks` を拡張）。

- 既存の目標入力・逆算・シナリオ・打ち手・CRM転記は変更なし
