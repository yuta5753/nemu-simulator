## 0. 要点（3行）

1. **会社の箱の中に店舗の箱を並べる**。店舗の箱は今の1店舗分の保存データそのもの。全社の数字は保存せず、表示のたびに各店舗から合算する
2. **店舗が1つのときは今と同じ画面**（全社タブなし）。2店舗以上で「全社」タブが現れ、①合算P/L＋本部費、②③店舗横並び、④目標ロールアップ、⑤全社サマリーを見せる
3. **店舗単位のファイル受け渡し**に対応。各店が単店版で入力したファイルを、本部が「店舗として追加／置き換え」できる

## 1. 決定事項（辻さん確認済み 2026-09-25）

## 2. データ構造

`version` を **4** に上げる。localStorage キーは `storeSim:v2` のまま。

```js
{
  version: 4,
  company: {
    name: '',                                        // 会社名（任意）
    hq: { labor: null, rent: null, ads: null, other: null },  // 本部費（年・円）。UIは万円入力
    plan: { requiredProfit: null, existingGrowthPct: 0 }     // 全社の必要営業利益（年・円）／既存客の伸び率
  },
  stores: [ /* 店舗バンドル（§2.1）。1件以上 */ ],
  activeStoreId: null,                               // null＝全社、または stores[].store.id
  meta: { createdAt, updatedAt }
}
```

### 2.1 店舗バンドル

**v3の保存データそのもの**（`store / benchmarks / categories / channels / mgmt / plan / meta`）に `store.id` を足したもの。

- `store.id`: `safeId(o.id, 's')`。タブ・切替・置き換えの識別に使う。`dedupeIds(stores, 's')` で重複を除去
- `store.name`: タブの表示名。空なら「店舗N」（Nは並び順）
- 既存の ①〜⑤ の画面・計算・貼り付けは **店舗バンドルを受け取って動く**ので変更しない

### 2.2 会社共通の値（目安値・表示期間）

`benchmarks` と `store.period` は **会社で共通**とする（横並び比較の物差しを揃えるため）。保存上は各店舗バンドルに同じ値を複製し、`syncShared(company, sourceIdx)` が更新のたびに他店舗へコピーする。

- 更新元＝いま操作している店舗。全社ビューで期間を切り替えた場合は `stores[0]` を更新元にして全店へ複製
- 全社ビューは `stores[0].benchmarks` と `stores[0].store.period` を参照する

> 例えると「各店の帳簿に同じ物差しのコピーを綴じておく」形です。店舗ファイルを単体で開いても物差しが付いてくるので、単店版との互換性が保てます。

### 2.3 読み込みと変換

| 入力 | 扱い |
|---|---|
| v4（`stores` あり） | そのまま `normalize` |
| v3以前（`stores` なし） | `normalizeStore` で店舗バンドル化し、店舗1つの会社に包む。`activeStoreId` はその店舗 |
| version > 4 | `unsupported version`（従来どおり） |

`normalize(obj)`（会社）は各バンドルを `normalizeStore` に通し、`stores` が空なら空店舗を1つ作る。`activeStoreId` が存在しない店舗を指す場合は **全社**（店舗が1つならその店舗）に倒す。

### 2.4 書き出し

| 操作 | 形式 | ファイル名 |
|---|---|---|
| ヘッダー「書き出し（JSON）」 | v4 会社ファイル（全店舗） | `会社名_全社_YYYYMMDD.json`（会社名が空なら `company`） |
| 店舗一覧「この店舗を書き出す」 | **v3 形式**の店舗ファイル（`version: 3`、`store.id` は含めたままでよい） | `店舗名_YYYYMMDD.json` |

店舗ファイルは単店版（v2.1 の公開ページ）でも読める。これが「各店が入力→本部が取り込む」運用の土台になる。

### 2.5 店舗ファイルの取り込み `parseStore(json)`

- v3以前のファイル → 店舗バンドルとして返す
- v4 で `stores.length === 1` → その店舗を返す
- v4 で `stores.length >= 2` → エラー `company file`（画面では「これは会社全体のファイルです。店舗ファイルを選んでください」）

## 3. 合算ルール（`Sim.calc.companyMgmt`）

計算モジュール（DOM非依存）に閉じ込め、Nodeテストで担保する。

### 3.1 経営数値の合算

各店舗の `mgmt` を項目ごとに次のルールで1つの `mgmt` 入力にまとめ、既存の `mgmtCore` に通す。

| 種別 | 項目 | ルール |
|---|---|---|
| 足し算 | revenue / buyers / newBuyers / newRevenue / activeCustomers / dormant / inventory / visits.* / costs.* / funnel.* | 値のある店舗だけを合計。1店舗もなければ null |
| 加重平均 | itemsPerBuyer | buyers で加重（両方ある店舗のみ）。なければ null |
| 名寄せ | products / replacement / channels | 名前（前後空白除去）が同じ行をまとめる。products: sales 合計・粗利率は sales 加重。replacement: pastBuyers 合計・cycleYears は pastBuyers 加重。channels: newCustomers・cost 合計 |
| 対象外 | categories / plan | 合算しない（店舗横並びで見る） |
| 前期 | prev | 同じルールで合算。値のある店舗が1つもなければ null |

**率はすべて合算後に再計算**する（粗利率＝合算粗利÷合算売上、リピート率＝合算(2回＋3回以上)÷合算来店回数計、など）。`mgmtCore` に通すので自動的にそうなる。

### 3.2 カバレッジ（空欄の注記）

`coverage`: 主要項目ごとに `{ n, total }`（値のある店舗数／全店舗数）。対象は revenue・buyers・newBuyers・newRevenue・activeCustomers・visits（3つ揃い）・costs.cogs・固定費4項目（揃い）・funnel（揃い）。

画面と印刷では、`n < total` の項目がある場合に **「空欄の店舗は合算に含めていません（売上 2／3店舗、人件費 1／3店舗）」** のように注記する。空欄を0扱いにして率を歪めない。

**売上をアンカーにする（2026-09-25 実装時の裁定）**: 率はすべて総売上を分母にするため、**総売上が空欄の店舗は経営数値の合算全体から外す**（費用・客数・商品なども足さない）。総売上のある店舗の中で個別の項目が空欄なら、上記のとおり項目単位で除外して注記する。こうしないと「2号店の売上だけ空欄」のとき費用だけが2店舗分になり、粗利率などが別の店舗集合どうしの割り算になるため。負の値は店舗単体と同じく0として扱う。

**揃っていない項目は合算しない（2026-09-25 最終レビュー後の裁定）**: 総売上のある店舗の間で、ある項目（仕入原価・人件費・購入客数・来店回数別など）が1店舗でも空欄なら、その項目の合算は null にして画面では「—」で示す（例: 2号店の人件費だけ空欄 → 全社の人件費・固定費・営業利益・損益分岐点・必要売上は「—」、粗利率は出る）。空欄の店舗を除いて足すと、率の分母（合算売上）と分子（費用など）が別の店舗集合になり誤った値が太字で出てしまうため。カバレッジ注記は従来どおり「人件費 1／2店舗」のように項目ごとに出す（固定費4項目をまとめて1件にはしない。どの項目が足りないかが分かる方が実用的）。前期（prev）も同じく、総売上のある全店に前期があるときだけ合算し、欠けていれば前期比較なしにする。

### 3.3 本部費

```
hqTotal              = 本部費4項目の合計（すべて null なら null）
店舗合算 営業利益     = mgmtCore(合算).operatingProfit        （本部費前）
全社 営業利益         = 店舗合算 営業利益 − hqTotal            （hqTotal が null なら本部費前の値をそのまま表示し「本部費未入力」と注記）
全社 固定費           = 店舗合算 固定費 + hqTotal
全社 損益分岐点       = 全社 固定費 ÷ 合算粗利率
全社 安全余裕率       = (合算売上 − 全社 損益分岐点) ÷ 合算売上
```

店舗別の営業利益は本部費を含まないことを、横並び表と全社レポートに明記する。

### 3.4 戻り値

```js
{
  available: bool,        // 合算売上が null でなければ true
  m: mgmtCore(合算),       // 店舗合算（本部費前）。prev も同形
  coverage: {...},
  hq: { labor, rent, ads, other, total },
  operatingProfitAfterHq, fixedCostsWithHq, breakEvenWithHq, safetyMarginWithHq
}
```

### 3.5 全社の必要売上 `Sim.calc.companyRequired(company)`

```
必要売上 = (全社 固定費 + 全社 必要営業利益) ÷ 合算粗利率
既存客の見込み = 合算 既存客売上 × (1 + 既存客の伸び率)
間口で稼ぐべき売上 = 必要売上 − 既存客の見込み（0未満は0）
```

条件不足（必要営業利益・固定費・粗利率のいずれか欠け）なら null。既存の `requiredRevenue` と同じ形で返す。

### 3.6 店舗横並び `Sim.calc.storeComparison(company, period)`

各店舗について次の指標を並べ、店舗が2つ以上ある指標には**店舗内の順位マーク**を付ける。

| 区分 | 指標 | 良い方向 |
|---|---|---|
| 経営 | 総売上・粗利率・営業利益（本部費前）・営業利益率・購入客数・新規客数・新規客比率・客単価・リピート率・安全余裕率 | 高いほど良い |
| 経営 | 人件費率・家賃比率・広告費率・損益分岐点売上 | 低いほど良い |
| 間口 | 新規獲得人数合計・平均LTV（期間）・期間累計売上・間口の目標売上（期間）・今の配分での売上（期間） | 高いほど良い |

順位マーク: 3店舗以上は最良「◎」最下位「△」その他「○」。2店舗は「◎」「△」。同値は同じマーク。null の店舗はマークなし。「間口の目標売上」「今の配分での売上」は計画値なのでマークを付けない。目安値がある指標（粗利率・人件費率・家賃比率・広告費率・リピート率）は「目安」列を足す。

戻り値: `{ metrics: [{ key, label, unit, better, bench, values: [{ storeId, value, mark }], company }] }`。`company` は合算値（率は再計算、間口は合計）。

## 4. 画面

### 4.1 店舗切替バー（ヘッダーとステッパーの間）

```
[ 全社 ] [ 本店 ] [ 2号店 ] [ 3号店 ]                     [ ＋店舗 ]
```

- **店舗が1つ**のとき: 「全社」タブを出さず、店舗タブ1つ＋「＋店舗」だけ。見た目は今とほぼ同じ
- タブ名＝`store.name`（空なら「店舗N」）。②「店舗の前提」の店舗名を変えると次の描画でタブに反映
- 「＋店舗」→ 小さな選択肢を出す: **「空の店舗を追加」「ファイルから追加」**。追加後はその店舗に切り替える
- 切替は `activeStoreId` の更新→ `renderStep()`。ステップ番号は維持する
- 期間切替（12/24/36ヶ月）は全店共通のまま（§2.2）

### 4.2 店舗タブを選んでいるとき

①〜⑤は**今と同じ**。`api.update(fn)` の `fn` には店舗バンドルを渡す。`api.getState()` も店舗バンドル。変更点は次の2つだけ。

- ヘッダー見出し: 「会社名｜店舗名｜売上シミュレーター」（会社名が空なら店舗名のみ。今と同じ）
- ④の「必要利益からの逆算」の注記に「店舗単位の数字です。本部費を含めた全社の逆算は全社タブで行います」を1行追加（2店舗以上のときのみ表示）

### 4.3 「全社」タブを選んでいるとき（新規モジュール）

`api.update` の `fn` には**会社の箱**を渡す（`updateCompany`）。`data-path` は会社基準（例: `company.hq.labor`）。

**① 経営数値（全社）**
1. 会社名（任意）
2. 本部費ブロック（人件費・家賃・広告宣伝費・その他。万円／年）。ガイド: 「本社の人件費・家賃など、どの店舗にも属さない費用。全社の利益にだけ効きます」
3. 店舗合算サマリー（読み取り専用）: 総売上・粗利・粗利率・固定費・営業利益（本部費前）・本部費・全社営業利益・損益分岐点（全社）・安全余裕率（全社）。カバレッジ注記（§3.2）
4. **店舗一覧**（管理）: 行＝店舗名 ／ 売上（年）／ 最終更新 ／ ボタン「開く」「この店舗を書き出す」「ファイルで置き換え」「複製」「削除」。下に「＋空の店舗を追加」「＋ファイルから店舗を追加」
   - 削除は確認ダイアログ。最後の1店舗は削除できない
   - 複製＝バンドルを深いコピー、`store.id` を新規、名前に「のコピー」
   - 置き換え＝その行の `store.id` と並び順は保ち、他をファイルの内容で置き換える（確認あり）

**② 間口カテゴリ（全社）**
店舗×指標の横並び一覧表（§3.6 の間口区分のみ＋カテゴリ数）。編集はしない。「編集は各店舗タブで行います」の案内と、各店舗名を押すとその店舗の②に飛ぶリンク。

**③ 診断（全社）**
1. 全社の健康度: 既存 `parts.mgmtKpis / waterfallSvg / costBars` に合算値を渡して再利用。滝図の末尾に「本部費」「全社営業利益」の段を足す（`waterfallSvg` に任意の追加段を渡せるよう引数を拡張）
2. **店舗横並び比較表**（§3.6）: 経営区分→間口区分の順。順位マークと目安列。5列超は横スクロール
3. コメント（`Sim.analysis.companyComments`）: 最大5件。例
   - 「粗利率が最も高いのは◯店（xx%）、最も低いのは△店（yy%）。差 z pt」
   - 「人件費率が最も高いのは◯店。店舗別の営業利益には本部費を含めていません」
   - 「本部費 xx万円は店舗合算の営業利益の yy% です」（本部費入力時）
   - 「空欄の店舗があるため、合算は一部の店舗のみで計算しています」（カバレッジ不足時）
   - 絶対的な閾値は使わない（v2.1と同じ方針）。業界値は含めない

**④ 目標と戦略（全社）**
1. 必要利益からの逆算（全社）: 入力＝全社の必要営業利益（万円）・既存客の伸び率。出力＝`companyRequired`（必要売上・現状・差・既存客の見込み・間口で稼ぐべき売上）
2. **ロールアップ表**: 行＝店舗、列＝現状売上（年）／店舗の必要売上（店舗タブで逆算済みなら）／間口の目標売上（期間）／今の配分での売上（期間・有効シナリオ）／到達率。合計行あり
3. 本部費の吸収チェック: 「店舗の必要売上の合計」と「全社の必要売上」を並べ、合計が下回る場合「店舗ごとの必要利益の合計では、本部費＋全社の必要利益に届きません（差 xx万円）」と表示。店舗への割り振りは自動では行わず、各店舗タブで調整する旨を案内

**⑤ レポート（全社）** 表紙＋4ページ
1. 全社の経営数値（合算KPI・滝図（本部費段あり）・費用比率・本部費・カバレッジ注記）
2. 店舗横並び比較（§3.6 の表）
3. 目標のロールアップ（④の1〜3）
4. 前提と計算式（合算ルール・本部費の扱い・店舗別利益は本部費前・目安値は会社共通）

印刷は既存と同じく `#panel-5` のみ。`beforeprint` の遅延描画も同じ仕組みを使う。

### 4.4 ヘッダーの「読み込み」

- v4 会社ファイル → 今の内容を置き換え（確認あり）
- v3 店舗ファイル → 「店舗1つの会社」として置き換え（確認あり）。店舗として**追加**したいときは店舗一覧の「ファイルから店舗を追加」を使う旨を確認文に添える
- 「サンプルを読み込む」→ **2店舗のサンプル**（本店＝今のサンプル、2号店＝本店の約0.6倍の数字・カテゴリ2つ・前期なし）。全社タブを開いた状態にする
- 「空で始める」→ 店舗1つの空の会社

### 5.1 `app.js` の API

```js
api        = { update(fn,{structural}), setStep, getState: () => activeStore, getCompany, period, setStore(id) }   // 店舗タブ用（fn には店舗バンドル）
companyApi = Object.assign({}, api, { update: updateCompany })                                                    // 全社タブ用（fn には会社の箱）
```

- `update` の後処理: `syncScenarios(activeStore)` → `syncShared(company, activeIdx)` → `updatedAt` → 保存 → 描画
- `updateCompany` の後処理: `syncShared(company, 0)` → `updatedAt` → 保存 → 描画
- モジュール表: 店舗タブ `{1: mgmt, 2: input, 3: diagnosis, 4: plan, 5: report}`、全社タブ `{1: company.mgmt, 2: company.entry, 3: companyDiag, 4: companyPlan.plan, 5: companyPlan.report}`

## 6. エラー処理・境界

| 状況 | 扱い |
|---|---|
| 店舗ファイルとして会社ファイル（2店舗以上）を選んだ | 「これは会社全体のファイルです。店舗ファイルを選んでください」 |
| 最後の1店舗を削除 | ボタンを無効化。案内「店舗は1つ以上必要です」 |
| 削除した店舗が表示中 | 全社（店舗が1つならその店舗）に切り替える |
| 全社で①の売上が全店舗空欄 | `available: false`。「店舗タブで経営数値を入れると全社の合算が表示されます」 |
| 本部費が未入力 | 全社営業利益＝本部費前の値を表示し「本部費未入力」を注記 |
| 一部店舗が空欄 | カバレッジ注記（§3.2） |
| 店舗が6つ以上 | 動作はするが横並び表は横スクロール。仕様上の上限は設けない |
