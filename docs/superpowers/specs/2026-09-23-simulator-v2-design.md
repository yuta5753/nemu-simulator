## 0. 要点（3行）

1. 今の「試算だけ」の1ページを、**①現状入力 → ②診断 → ③目標と戦略 → ④レポート**の4ステップに組み替える。ページは1枚のまま、コードは役割ごとにファイル分割する。
2. 判定の物差しは**自店内の相対比較**を基本にし、**目安値・前期の数字は任意入力**。データが少ない店でも動き、入れるほど診断が濃くなる。
3. ねむねむCRMの実測ビュー（`v_entry_cohort`）と**同じ項目名・同じ意味**で入力欄を作り、貼り付けで取り込める。他店はExcelから同じ列順で貼れる。

## 1. 目的・利用者・成功条件

### 1-1. 目的
店舗の数字（新規獲得・間口商品・追加購入・購入までの期間）から、**どこが強く、どこが弱く、どのレバーをどれだけ動かせば目標に届くか**を、その場で設計できる資料にする。

### 1-2. 利用者と使い方
| 場面 | 誰が | どう使う |
|---|---|---|
| コンサル同席 | 辻さん＋店主 | 辻さんが説明しながら数字を入れ、診断結果を叩き台に戦略を一緒に組む |
| 店主単独 | 店主 | 「？」ガイドを開きながら自分で入力・診断・目標設定を行う |
| ねむねむはうす | 辻さん | CRMの実測を貼り付けて現状を再現し、目標をCRMの目標入力フォームへ転記する |

### 1-3. 成功条件
- 数字を入れると、**間口ごとの位置づけ（伸ばす／育てる／集客を寄せる／見直す）**と**一番弱い要素**が文章で出る
- 目標売上を入れると、**レバー別の必要改善幅**（新規なら＋○人、追加率なら＋○pt…）が逆算で出る
- 戦略（レバー配分＋打ち手）をシナリオ3本まで保存・比較できる
- ①〜③をA4数枚のレポートとして印刷（PDF保存）できる
- 店舗ごとのデータをJSONで持ち回れる（書き出し／読み込み）
- 今の使い方（GitHub Pagesを開く／HTMLをダブルクリックで開く）は変わらない。外部ライブラリなし

## 2. 全体構成

### 2-1. 画面の流れ（1ページ・ステッパー）

```
┌──────────────────────────────────────────────────────────┐
```

## 3. データ構造（state）

保存・書き出しの単位。バージョン番号を持ち、将来の変更時に変換できるようにする。

```js
{
  version: 2,
  store: {
    name: "",                 // 店名
    fiscalLabel: "",          // 例 "2026年度（4月〜3月）"
    cogsRate: 50,             // 原価率 %
    fixedCostMonthly: 0,      // 固定費 円/月（任意）
    period: 3                 // 選択中の期間 1|2|3
  },
  benchmarks: {               // 目安値（任意・空なら未使用）
    sameDayRate: null,        // 同日追加率 %
    laterRate: [null,null,null], // 後日追加率 % 1/2/3年
    laterAov:  [null,null,null], // 後日追加単価 円
    daysToAddon: null         // 初回→追加購入 日数
  },
  categories: [               // 間口カテゴリ（今の「集客商品」を継承・名称自由）
    {
      id: "c1",
      name: "枕（フィッティング）",
      entryPrice: 12000,      // 間口単価（円・単品）
      newCustomers: 40,       // 新規獲得人数（期間の対象コホート合計）
      sameDay: { rate: 0, aov: 0 },              // 同日追加（任意・空=0）
      later: [ {rate:35, aov:15000}, {rate:55, aov:26000}, {rate:68, aov:34000} ], // 後日追加 1/2/3年累計
      daysToAddon: null,      // 初回→追加購入までの平均日数（任意）
      nextProducts: "",       // 主な展開商品（自由記述）
      prev: null              // 前期の数字（任意）{ entryPrice, newCustomers, sameDay, later, daysToAddon }
    }
  ],
  channels: [                 // 集客経路（任意）
    { id:"ch1", name:"Google広告", newCustomers: 0, cost: 0 }
  ],
  plan: {
    targetRevenue: [null,null,null],   // 目標売上（期間別・円）
    activeScenario: 0,
    scenarios: [                        // 最大3本
      {
        name: "標準",
        levers: {                       // カテゴリID → レバー変化量
          "c1": { newPct: 0, sameDayPt: 0, laterPt: 0, aovPct: 0, entryPricePct: 0 }
        },
        tactics: [                      // 選んだ打ち手
          { lever:"new", categoryId:"c1"|null, text:"…", owner:"", due:"", fromLibrary:true }
        ],
        memo: ""
      }
    ]
  },
  meta: { createdAt, updatedAt }
}
```

### 3-1. 用語の定義（CRMの設計図§3と同じ）
| 用語 | 定義 |
|---|---|
| 間口カテゴリ | 新規客が最初に買う商品のくくり。名称は店ごとに自由 |
| 間口単価 | 初回購入日の間口商品の金額（単品） |
| 新規獲得人数 | その間口で初めて買った人数。**1決算期（1年）に獲得する1コホート**として扱い、期間累計売上は「そのコホートが1年／2年／3年で生む売上」を指す（旧版と同じ考え方） |
| 同日追加 | 初回購入日に間口以外を買った分。率の母数は新規獲得人数。単価は「追加した人1人あたりの平均額」 |
| 後日追加 | 初回購入日より後、1年／2年／3年以内に買った分。率・単価は期間ごとの累計 |
| 初回→追加購入までの日数 | 初回購入から最初の後日追加までの平均日数 |
| 計画LTV（期間） | 間口単価 ＋ 同日率×同日単価 ＋ 後日率(期間)×後日単価(期間) |

- 旧版（v1）の「追加単価／追加率」は後日追加として読み替える（同日は0）。旧版に保存機能はないため、変換はサンプル初期値の定義のみで完結する

## 4. ステップ① 現状入力

### 4-1. ブロック構成
1. **店舗共通**：店名／決算期ラベル／原価率／固定費（任意）
2. **間口カテゴリ**（カード形式・追加/削除可・今のカードUIを拡張）
   - 必須：名称・間口単価・新規獲得人数・後日追加（1/2/3年の率と単価）
   - 任意：同日追加（率・単価）・初回→追加購入日数・主な展開商品・前期の数字（折りたたみ）
   - カード下部に「顧客あたりLTV（選択期間）」を即時表示（今と同じ）
3. **集客経路**（任意・折りたたみ）：経路名／新規人数／費用 → CPAを自動表示。経路の新規合計とカテゴリの新規合計が食い違う場合は注記のみ（一致は求めない。経路＝入口の話、カテゴリ＝買った物の話で軸が違う）
4. **目安値**（任意・折りたたみ）：同日率／後日率／後日単価／日数。「業界平均や前年実績など、比べたい数字があれば」と案内
5. **CRM/表から貼り付け**（折りたたみ）：テキストエリアに貼る → 解析結果のプレビュー表 → 「取り込む」で反映

### 4-2. 貼り付け取り込みの仕様（paste.js）
- 入力：タブ区切り（Excel／CRM画面からのコピー）またはカンマ区切り。1行目はヘッダー
- 認識する列（ヘッダー名で判定。日本語・英語どちらでも可。順不同）

| 取り込み先 | 認識するヘッダー |
|---|---|
| name | `間口カテゴリ`, `entry_category`, `カテゴリ` |
| period（1/2/3） | `期間`, `period_years` |
| newCustomers | `新規獲得数`, `new_customers`, `新規` |
| entryPrice | `間口単価`, `entry_unit_price`（または `entry_sales` ÷ `new_customers` で算出） |
| sameDay.rate | `同日追加率`, `sameday_addon_rate` |
| sameDay.aov | `sameday_addon_sales` ÷ `sameday_addon_customers` で算出（列が揃う場合） |
| later[p].rate | `後日追加率`, `later_addon_rate` |
| later[p].aov | `later_addon_sales` ÷ `later_addon_customers` で算出 |
| （参考） | `measured_ltv` は取り込まず、取り込み後の計画LTVと並べて差を表示 |

- 同じカテゴリの行が複数（コホート月ごと）ある場合は、**人数で加重平均**してカテゴリ1行に束ねる（`cohort_month` 列があれば月ごとに集計されているとみなす）
- 期間列がなければ「選択中の期間」の列として取り込む
- 既存カテゴリと名称が一致すれば上書き、なければ新規カテゴリとして追加。取り込み前にプレビューで「上書き／追加」を明示
- 数字にならない値・負の値はその欄をスキップし、プレビューに警告を出す。取り込みは中断しない
- `初回→追加購入日数` はCRMの実測ビューに存在しないため手入力（将来CRM側に列が増えたら同名ヘッダーで自動対応）

### 4-3. 入力の検証
- 率は0〜100、金額・人数は0以上。範囲外は赤枠＋注記で知らせるが、計算は0または上限で丸めて続行
- 後日追加率・単価は「累計」なので、1年＜2年＜3年でない場合は黄色の注記（入力ミスの可能性を示す。強制はしない）
- 新規獲得人数が10人未満のカテゴリは診断で「判定保留」扱い（CRMの信号ルールと同じ基準）

## 5. ステップ② 診断

すべて純関数（analysis.js）。入力から自動で出す。**業界値は埋め込まない**。

### 5-1. 現状サマリー（数字の全体像）
- 新規合計／加重平均LTV／期間累計売上／粗利／（固定費があれば）営業利益：今のKPIカードを継承
- 間口カテゴリ別の一覧表：新規・間口単価・同日率・後日率・追加単価・LTV・売上・売上構成比
- 集客経路があれば：経路別CPAと「粗利LTV ÷ CPA」（広告費の回収倍率）

### 5-2. 間口ポートフォリオ（4象限）
- 横軸 **集客力** ＝ 新規獲得人数 × 間口単価（＝間口売上）
- 縦軸 **展開力** ＝ 計画LTV − 間口単価（＝新規1人が間口の後に生む追加額）
- 境界＝カテゴリ間の**中央値**（カテゴリ2件のときは平均、1件のときは象限図を出さず一覧のみ）
- 各象限のラベルと意味

| 象限 | ラベル | 読み方 |
|---|---|---|
| 高集客 × 高展開 | **主力（伸ばす）** | 集客も展開も効いている。広告・売場・人員を寄せる先 |
| 高集客 × 低展開 | **入口止まり（育てる）** | 人は入るが次につながらない。展開商品・フォローの設計が課題 |
| 低集客 × 高展開 | **隠れた優良間口（集客を寄せる）** | 入れば伸びる。入口を太くする価値がある |
| 低集客 × 低展開 | **見直す** | 位置づけを再検討（廃止ではなく「役割の再定義」） |

- 点の大きさ＝売上構成比。母数10人未満はグレー表示＋「判定保留」
- 描画はインラインSVG（ライブラリ不使用）

### 5-3. ボトルネック診断（「効きどころ」と「弱点」を分けて出す）

**(a) 効きどころ**（常に出る）：各カテゴリで、標準的な改善幅を当てたときの売上増を比べ、最も効くレバーを示す
- 標準幅：新規＋10%／同日率＋5pt／後日率＋5pt／追加単価＋10%／間口単価＋5%
- 出力例：「枕は『後日追加率＋5pt』が最も効く（＋¥180,000）。次点は新規＋10%」
- 店全体でも同じ計算をして「店として最も効くレバー」を1つ示す

**(b) 弱点**（比較対象があるときだけ出る）
- 目安値がある項目：実績 ÷ 目安 が最も低い項目を弱点とし、差を示す
- 前期がある項目：前期比の落ち幅が最も大きい項目を示す
- どちらもなければ：カテゴリ間の相対比較で「店の加重平均より低い率」を列挙し、末尾に「目安値か前期を入れると弱点判定が出ます」と案内

**(c) 一言コメント**：テンプレートで生成。断定を避け「〜の可能性があります」「〜が課題になりやすい構造です」の言い回し。判断材料としての数字を必ず添える

### 5-4. 購入までの期間の分析
- カテゴリ別に「初回→追加購入までの平均日数」を横棒で並べる
- フォローの打ち時の提案：同日（接客中のクロスセル）／平均日数の半分の時点／平均日数の時点の3点を「接触の目安」として表示
- 整合チェック：平均日数が選択期間（365×期間）を超えているのに後日追加率が高い場合は「日数か率のどちらかが入力ミスの可能性」と注記

### 5-5. データ不足時の扱い
- 入力が足りない項目は「未入力」と表示し、その項目に依存する診断は出さない（0として誤診断しない）
- 判定保留（母数10未満）はグレーで表示し、コメントに「人数が増えてから判断」と明記

## 6. ステップ③ 目標と戦略

### 6-1. 目標設定と逆算
- 期間別に「目標売上（期間累計）」を入力。現状売上との差＝ギャップを表示
- **レバー単独で達成する場合の必要量**を4通り並べる（すべて全カテゴリ一律に効かせた場合）

| レバー | 逆算式（G＝ギャップ） |
|---|---|
| 新規獲得 | 倍率 k＝目標÷現状 → 必要な追加人数＝Σ新規×(k−1) |
| 同日追加率 | Σ 新規×(p/100)×同日単価 ＝ G → 必要pt p（同日単価が未入力のカテゴリは対象外。全て未入力なら「—」） |
| 後日追加率 | Σ 新規×(p/100)×後日単価 ＝ G → 必要pt p |
| 追加単価 | Σ 新規×(同日率×同日単価＋後日率×後日単価)×(m−1) ＝ G → 必要% (m−1)（同日・後日の単価に同じ倍率を掛ける） |
| 間口単価 | Σ 新規×間口単価×(m−1) ＝ G → 必要% (m−1) |

- レバーは③のスライダーと同じ5本で揃える（効きどころ診断とも同じ5本）
- 現実性の目安として、各レバーに「今の値→必要値」を併記（例：後日追加率 55% → 63%）
- 必要値が100%を超える率など現実的でない場合は「このレバー単独では届きません」と表示

### 6-2. レバー配分（シナリオ）
- カテゴリごとに5つのスライダー：新規％／同日率pt／後日率pt／追加単価％／間口単価％（今の感度分析の拡張）
- 画面上部に「目標到達率」バーを常時表示。動かすと即時更新
- 「均等に割り振る」ボタン：ギャップを、入力のある（単独逆算が「—」でない）レバーに等分して初期値を置く（出発点の提案。あとは手で調整）
- シナリオは最大3本（初期名：保守／標準／強気）。コピー・名称変更・削除可。比較表で3本の売上・粗利・到達率を横並び

### 6-3. 打ち手カード
- レバーごとに打ち手ライブラリ（tactics.js）からチェックで選ぶ＋自由記述。担当・期限を書ける
- ライブラリは**業種に依らない定型**のみ（例）

| レバー | 定型打ち手の例 |
|---|---|
| 新規獲得 | 検索広告の入口商品訴求／来店前の不安を解く相談導線／紹介特典／SNS動画 |
| 同日追加 | 接客の提案手順を台本化／セット提案／間口商品と相性のよい付帯品の陳列 |
| 後日追加 | 購入後○日フォロー（期間分析の日数を自動で差し込む）／LINE・DMの定期接点／点検・買替の案内 |
| 追加単価 | 展開商品の上位グレード提案／まとめ買い／年間プラン |
| 間口単価 | 入口商品の見直し／フィッティング等の付加価値化 |

- 定型文は編集可。店固有の打ち手は自由記述で追加

### 6-4. CRM転記用の出力（ねむねむはうす向け・他店は無視できる折りたたみ）
- 選択中シナリオを、CRMの目標入力フォームの項目順で表にする：間口カテゴリ／期間／間口単価／目標新規獲得人数／追加購入単価／追加購入率
- CRMの目標は追加を1本（率×単価）で持つため、同日と後日は次で束ねる
  - 追加購入率 ＝ 1 −(1−同日率)(1−後日率)（同日と後日が独立に起きる仮定）
  - 追加購入単価 ＝（同日率×同日単価 ＋ 後日率×後日単価）÷ 追加購入率
  - 表の脚注に「独立の仮定で束ねた値」と明記
- 「コピー」ボタンでタブ区切りをクリップボードへ

## 8. 保存・読込

- **自動保存**：入力のたびに `localStorage["storeSim:v2"]` へ保存。起動時に復元
- **書き出し**：JSONファイル（`{店名}_{YYYYMMDD}.json`）。店舗ごとに持ち回る
- **読み込み**：JSONを選択 → `version` を確認 → 未来のバージョンなら拒否、過去なら変換 → 反映。読み込み前に「今の内容を置き換えます」と確認
- **初期化**：「サンプル（寝具店）を読み込む」「空で始める」の2ボタン。今の初期値（枕・敷きもの）はサンプルとして残す
- 注意書き：「ブラウザ内の保存は同じ端末・同じブラウザでしか残りません。持ち回るときは書き出しを使ってください」

## 11. エラー処理

| 状況 | 挙動 |
|---|---|
| 計算で0除算（新規0など） | 結果は「—」表示。エラーで止めない |
| 貼り付けの解析失敗 | プレビューに理由を表示（列が見つからない／数字でない）。反映しない |
| JSON読み込み失敗 | 「ファイルの形式が違います」と表示。今の内容は保持 |
| localStorage が使えない（プライベートモード等） | 自動保存を諦め、ヘッダーに「自動保存が無効です。書き出しをお使いください」と表示 |

## 12. テスト方針

- **純関数の自動テスト**（`node tests/run.js`・依存なし）
  - calc：LTV式・期間別売上・粗利・営業利益・逆算4式（既知の入力→期待値）

  - paste：日本語ヘッダー・英語ヘッダー・コホート月の加重平均・不正値の警告・期間列なし
  - state：旧初期値→v2変換・JSON往復・未来バージョン拒否

  - ステップ遷移・期間切替・保存/読込・貼り付け・印刷プレビュー・スマホ幅
